# 增幅權重倍率擴樣研究：2026-10-03

> 歷史研究存檔（2026-11-14 從 branch `codex/augment-weight-expansion` 的 commit `f71b06631d` 整理進來）。16.19 起增幅池檔已清空、移到伺服器端，網站池子凍結在 16.18，這份結果不再更新。文中提到的 `src/aram_nn/augment_weight_study.py`、`scripts/study_augment_weights.py` 與單元測試沒有併入 main，只留在該 commit；要重跑時從那裡取出，CLI 依現行規則放到 `scripts/research/`。

有效發放代理事件從 **9,539 擴到 21,462**，增加 125%。16.19 的獨立結果支持「權重 200 相對 100 約 2 倍」的量級；兩版合併的描述估計為 **1.965 倍，95% CI 1.852–2.099**。同口徑的區間寬度比舊樣本縮窄約 **35%**。這表示抽樣精度改善，不能證明偏差消失或已找到 Riot 的精確發放公式。

研究以分 patch 結果為主。稀有度間存在明顯異質性，不能把合併倍率當作所有銀／金／棱彩增幅都通用的常數；也不測量一般三選一選項的出現率。此次只更新研究成果，未更新或發布網站圖表。

## 與舊研究相同的口徑

1. 第四個正常增幅（index 3）必須是 King Me、Transmute: Prismatic、Transmute: Gold 或 Transmute: Chaos，只分析其後增幅。
2. 排除發放出的 Transmute 本身，逐次排除當時已持有增幅。
3. 候選集依增幅的稀有度，固定使用歷史 16.18 池表、最高來源池權重、舊版 blocked/dead/norandom，以及舊版已識別的八個未曾隨機發放增幅。沒有用 16.19 結果重挑排除規則。
4. 每次事件建立候選權重曝露。權重桶的實際事件數 O 除以候選均勻發放下的期望 E，再以權重 100 的 O/E 正規化。
5. 原始 16.18 cache 與重新唯讀掃描均得到 9,539 次事件，五個權重桶 O/E 倍率逐項相等，誤差小於 1e-10。

這個辨識窗只是 final augment list 的保守代理，不是完整隨機發放紀錄。原始窗中仍出現 norandom 增幅，顯示不能把每個尾端欄位直接當作已確認的合法隨機發放。依舊口徑排除這些事件，並保留計數，不能宣稱代理完全無選擇偏差。

16.19 池表沿用 frozen 16.18 權重；目前資料不能獨立確認伺服器內部池權重是否完全未變。

## 稀有度差異

兩版描述摘要中的權重 200 / 100：

| 稀有度 | 有效事件 | 權重 100 實際發放 | 倍率與 95% CI |
|---|---:|---:|---:|
| 銀色 | 2,120 | 107 | 2.844（2.375–3.464） |
| 金色 | 3,701 | 120 | 3.284（2.773–3.995） |
| 棱彩 | 15,641 | 877 | 1.698（1.588–1.818） |

銀／金的基準桶較稀疏，因此區間仍寬。整體結果主要由棱彩構成。O/E 是曝露校正摘要，還受候選集組成影響，不能把這些桶比值解讀成伺服器固定倍率或稀有度的因果效果。

## 條件模型與時間驗證

模型對每次事件給候選增幅 a 的條件機率 `P(a) = max_weight(a)^γ / Σ max_weight(candidate)^γ`。O/E 比值與 `2^γ` 不是同一個 estimand：前者是混合候選集下的經驗摘要，後者是模型假設下同一候選集內兩個增幅的比值。

| 範圍 | γ 點估計 | 95% 同局 cluster sandwich CI |
|---|---:|---:|
| 16.18 | 1.161 | 1.089–1.234 |
| 16.19 | 1.114 | 1.049–1.178 |
| 兩版描述摘要 | 1.135 | 1.087–1.183 |

舊研究使用 0.1 的網格，報 γ=1.2；本次連續最佳化重現同一資料時 γ=1.161，差異來自網格解析度。新舊 γ 差異為 -0.0477，近似 95% CI -0.1445 至 0.0491，未能確認兩版本間有差異；沒有確認差異不等於證明完全不變。兩版模型隱含的 200 / 100 為約 2.195，不能用來替換經驗摘要 1.965 而不改指標定義。

16.19 的時間界線由前 70% 對局的日期決定，為 2026-09-29 07:31:31 UTC；前段 8,282 次有效事件，後段 3,641。前段 γ=1.105，後段 γ=1.134。後段平均條件 log loss：

| 模型 | 後段 log loss（越低越好） |
|---|---:|
| γ=0，均勻 | 3.594606 |
| γ=1，線性 | 3.532947 |
| γ=1.2，舊粗網格值 | 3.532384 |
| 前段估計 γ=1.105 | 3.532247 |

前段擬合相對線性的 paired 差為 -0.000701，95% 同局 bootstrap CI -0.001667 至 0.000353，跨過零。因此雖全量資料 γ 稍高於 1，尚不值得在產品中推廣更精細的非線性公式。權重有訊號、近似成比例的量級受支持；精確公式沒有獲得驗證。

此外，前／後段 O/E 的 200 / 100 分別為 1.823 / 2.255，區間有重疊但點估計不同，顯示曝光組成與稀疏基準桶可使經驗倍率移動。

## Guardrails 與決策

- 新版沒有候選池外、舊 blocked、舊 dead 或已持有的發放代理事件；所有對局通過結構檢查。
- 舊「未曾隨機發放」名單在新版出現六次：Wooglet's Witchcap 2、Ultra Hydra 2、Multishot 1、Flash 2 1。依固定口徑排除；不能再把這份名單當永久、絕對排除的真相。
- 全部採最高權重是為保持同口徑，這次沒有重新比較加總權重／池數模型，不能宣稱本次又獨立證明 max 優於其他規則。
- 合併後抽樣區間變窄，但版本凍結、發放代理辨識與候選集失配的系統誤差不會因增加 n 消失。
- **決策：保存分版本結果與合併描述摘要；維持「約 2 倍」量級說明，不發布精確公式，不自動替換網站圖表。**

## 可重現輸出

程式：`src/aram_nn/augment_weight_study.py`；CLI：`scripts/study_augment_weights.py`；預先 manifest：本文附錄。

本機 `outputs/augment-weight-expansion/` 保存 `frozen_rules.json`、`events_16.18.json.gz`、`events_16.19.json.gz`、`legacy_reference_16.18.json`、兩版 `results_*.json`、`results_combined_descriptive.json` 與 `lineage.json`。事件 cache 只保留匿名局內 cluster index、時間、英雄／增幅與候選權重數量，不包含 game_id 或玩家身份；不作 public payload。

```powershell
python scripts/study_augment_weights.py collect --db D:/Projects/CODING/aram-winrate-nn/data/lcu/games.db --patch 16.18 --cutoff-ms 1790117483629
python scripts/study_augment_weights.py collect --db D:/Projects/CODING/aram-winrate-nn/data/lcu/games.db --patch 16.19 --cutoff-ms 1791015973303
python scripts/study_augment_weights.py analyze --patch 16.18 --bootstrap 2000
python scripts/study_augment_weights.py analyze --patch 16.19 --bootstrap 2000
python scripts/study_augment_weights.py combine --bootstrap 2000
```

重新掃描 live DB 可能補收較早對局，因此舊 snapshot 的精確重現以保存的事件 cache 與身分摘要為準。重建 frozen rules 的 `import-legacy --scratch` 僅供可信的本機舊 cache，不讀外來 pickle。不要刪除保存的 frozen rules 與事件 cache 後才期待 live DB 還原相同 snapshot。

環境：Python 3.13.1、NumPy 2.4.4、SciPy 1.17.1；seed 20261003。候選排除、發放窗、似然估計、同局 bootstrap 與 record gate 的五項單元測試通過；舊樣本事件數與每桶倍率重現通過。

## 附錄：預先固定的研究口徑

- 決策：判斷歷史隨機發放倍率能否以更多資料縮小不確定性；不直接改網站、不宣稱一般三選一選項機率。
- 假說：16.19 仍大致遵循以最高來源池權重加權的發放；先檢驗跨版本穩定性，不能直接把版本混成同一環境。
- 單位：隨機發放事件；不確定性以對局為 cluster，保留同局事件的相依性。
- 控制：重現 16.18 的 9,539 事件；固定舊候選池、最高權重、已持有排除、舊 blocked/dead/norandom 排除，以及舊研究已識別的八個從未隨機發放增幅。
- 處理：同樣篩選方法套用新增的 16.19 對局。新版本不重新按結果挑排除項目。
- 來源：本機 `data/lcu/games.db`，queue 2400，16.18 / 16.19 分開報告。LCU 是 TW 收集環境；DB 沒有逐局 region 欄，無法獨立重驗每局區服。
- 範圍：16.18 已有 536,935 場；16.19 盤點約 655,351 場，2026-09-23 至 2026-10-03。實際唯讀掃描以單一 SELECT snapshot 為準，保存實際筆數、時間極值、去重身份摘要與 DB 檔案資訊。
- 隨機發放窗：四個正常增幅的最後一個（index 3）為 King Me / Transmute: Prismatic / Transmute: Gold / Transmute: Chaos，只取其後事件；排除 Transmute 發放本身。這是與舊研究相同的保守識別方式，不等同於完整發放 log。
- 品質：新掃描必須有十名參與者、雙方各五名、英雄 metadata 一致、可解析增幅與時間；排除要逐類計數。game_id 為唯一身份，不以組合去重。

- 主指標：後段條件 log loss 與各權重 O/E 相對 100 的倍率；同時報同局 cluster bootstrap 95% CI、按稀有度結果與兩版本差異。
- γ 模型：候選增幅條件機率與最高來源池權重的 γ 次方成比例。O/E 倍率是候選池曝露校正後的經驗摘要，並非同一候選池中的精確權重倍數。
